# Security headers

The application emits the security policy at the request boundary in [`proxy.ts`](../../proxy.ts). Each matched request receives a fresh nonce, and the same policy is forwarded on the request headers so Next.js can attach the nonce to framework scripts and inline styles during dynamic rendering. The root layout opts into dynamic rendering because a build-time static page cannot receive a request nonce.

The policy permits only same-origin scripts and styles, with the request nonce and `strict-dynamic`. It also blocks framing, objects, insecure upgrades, cross-origin opener sharing, and unapproved device capabilities. `next.config.ts` supplies the static headers (`HSTS`, `nosniff`, `DENY`, referrer policy, permissions policy, COOP, and DNS prefetch control) for all routes, including API and 404 responses.

Development adds `unsafe-eval` for React diagnostics and `unsafe-inline` for development styles. Production never adds either directive. Next's built-in 404 document emits stable inline style attributes, so production includes `unsafe-hashes` and the five reviewed SHA-256 hashes for that framework-owned document; application styles remain nonce-bound. If a future dependency emits another nonce-less inline style, the policy must be changed to a reviewed hash or `unsafe-hashes`; `unsafe-inline` must not be enabled in production. The production Playwright test checks the complete directive map, a unique nonce per response, and the absence of CSP violations on `/`, the smoke route, and a 404.

The bundle scanner follows the browser delivery boundary under `.next/static` and does not inspect server page bundles as browser artifacts. It checks JavaScript, CSS, and source maps for credential-shaped values and values selected from explicit secret environment names. Generic variables such as `PATH`, `NODE_ENV`, and one-character flags are excluded. A public environment variable with a secret-like name fails before bundle delivery can occur; diagnostics report file and offset without printing the value.
